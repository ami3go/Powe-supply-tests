# Automotive Power Supply Validation Test Matrix

_Last updated: 2026-09-20 · 100-row validation matrix · N6700/N6775A/N6791A bench mapping · ISO 26262 evidence mapping · internal-requirement review_

## Scope

This matrix is intended for validation of an automotive direct-current power supply, direct-current converter, or electronic control unit power stage. The available bench includes a **Keysight N6700 modular power system fitted with an N6775A source module and an N6791A electronic-load module**, plus a digital oscilloscope and thermal chamber.

It combines:

- converter characterization and dynamic behavior;
- automotive battery and supply disturbances;
- protection and fault-injection tests;
- thermal, environmental and endurance tests;
- conducted-transient, EMC and ESD tests;
- 48 V and voltage-class-B/high-voltage references where applicable;
- design-verification tests such as control-loop stability, component stress and hot-plug behavior;
- functional-safety verification and explicit fault-reaction evidence where the power supply is safety-related;
- audit-ready execution metadata for applicability, operating state, samples, pre/post checks, timing/recovery, evidence and measurement traceability.

> **Important:** this is a planning matrix, not a substitute for a licensed standard or the customer/vehicle-manufacturer component requirement specification. Exact severity, waveform, source impedance, repetitions, operating mode, functional-status requirement, sample count and acceptance limits shall be taken from the applicable contract specification and standard edition.

> **Internal-source handling:** project-specific and closed-source material was used to improve coverage, corner cases, evidence requirements and fault-injection depth. Proprietary source identities are intentionally not reproduced here. Where such material affects a row, the basis is described generically as **internal requirement / safety analysis**; contractual limits remain controlled by the project requirement set.

## Installed N6700 hardware and limitations

- **Keysight N6775A:** programmable DC source, 0–60 V, up to 5 A and 300 W. It supports remote sensing, list/arbitrary-waveform operation, adjustable slew rate and integrated voltage/current measurement. It is non-regenerative and cannot directly generate negative voltage.
- **Keysight N6791A:** programmable DC electronic load, up to 60 V, 20 A and 100 W. It supports constant-current, constant-voltage, constant-resistance and constant-power modes, adjustable slew rate, list/arbitrary-waveform operation and synchronized voltage/current digitization.
- **Electrical logging:** use N6700 measurements continuously retrieved to the control computer. External environmental channels still need their own sensors/acquisition when the chamber does not provide them.
- **Precision measurement:** retain a calibrated precision DMM or power analyzer when the required uncertainty is tighter than the N6700 module specifications, when independent verification is required, or when measuring nodes not connected to the source/load terminals.
- **Fast events:** retain the external oscilloscope and appropriate voltage/current probes for ripple, ringing, inrush, protection transitions, micro-interruptions and automotive transients.
- **Source limitations:** negative voltage, regenerative sinking, very fast/high-energy transients, compliant EMC stimuli, HV insulation testing and many internal fault injections require external equipment.

### Present setup status

- **Available** — the installed N6700 modules, oscilloscope and thermal chamber can normally execute the test within their voltage/current/power/dynamic limits.
- **Available/Partial** — useful coverage is possible on the current bench, but formal or worst-case execution may need additional capability depending on the project limits.
- **Partial** — the N6700 bench is useful for source, load or measurement, but an additional fixture or instrument is required.
- **Additional equipment required** — dedicated transient, EMC, environmental, insulation, high-voltage or other specialized equipment is required.

### ISO 26262 applicability legend

The A–D columns use the evidence grading from the companion [`iso26262-asil-test-mapping.md`](iso26262-asil-test-mapping.md):

- **REQ** — execute and trace to the applicable safety requirement or safety mechanism.
- **++** — method highly recommended at this ASIL; apply it or document a rationale for omission.
- **+** — recommended.
- **o** — no recommendation for or against.
- **T** — only when triggered by HARA/FMEA/FMEDA/DFA/architecture; once triggered, treat as required.
- **n/a** — underlying requirement does not exist at that ASIL.
- **—** — not driven by ISO 26262.
- **FI+/FI++/WC+** — fault-injection or worst-case evidence grade.
- A trailing **\*** means the row note defines an applicability condition.

### Mandatory execution metadata

Every executed test ID shall also carry the following metadata in the executable test definition and report:

| Field | Required content |
|---|---|
| Applicability / trigger | Why the test applies; requirement/safety-analysis item |
| DUT operating mode | OFF, startup, run, sleep, degraded, shutdown; include ISO/LV operating mode when applicable |
| Expected functional state | Normal, degraded, reset, shutdown, latched safe state, automatic retry, manual/power-cycle recovery |
| Sample count / rationale | Number of DUTs and justification |
| Pre-stress parameter check | Baseline measurements before stress |
| Post-stress parameter check | Re-measurement and drift from baseline |
| Fault timing / recovery | Fault onset → detection (FDTI) → safe/degraded state (FRTI), restart delay/latch/recovery condition |
| Evidence package | Waveforms, CSV/logs, thermal data, DTC/status registers, photos, instrument settings, automation transcript |
| Measurement traceability | Instrument ID, calibration status/date, range/bandwidth, probe/fixture, uncertainty/guard band |
| Requirement traceability | Standard/customer/internal requirement or safety-analysis item |
| Automation traceability | Test-software version/commit, instrument configuration and status/error queue |

**Guard-band rule:** equipment protection limits and test acceptance limits are separate. Driver/instrument safety limits protect the bench and DUT; pass/fail limits come from the applicable product/customer requirement. Near a limit, include measurement uncertainty and an agreed guard-band decision rule.

### Combined-corner campaign

Do not infer combined-stress robustness from independent single-factor passes. At minimum, instantiate applicable combinations as explicit test cases linked to the parent IDs:

- minimum Vin + maximum load + maximum operating temperature;
- cold crank / starting profile + simultaneous load step;
- maximum Vin + fast load transient + hot power stage;
- enable glitch at the switching threshold during startup and shutdown;
- protection fault injected during startup;
- recovery from overload/UVLO/thermal shutdown while a second supply disturbance is present;
- maximum/minimum effective output capacitance at Vin/load/temperature corners;
- aged/post-stress parameter drift combined with the closest protection threshold.

For every combination, record which parent test IDs and requirements it closes; do not create anonymous ad-hoc bench cases that cannot be traced later.

## Recommended execution order with the current bench

A practical sequence that minimizes the risk of destroying an uncharacterized prototype is:

1. **Baseline:** PS-001…PS-007, PS-026, PS-031.
2. **Stability first:** PS-021…PS-023 and PS-025 — an unstable loop invalidates most later results.
3. **Dynamic behavior:** PS-024 (before any hot-plugging), then PS-008…PS-013, PS-027, PS-028.
4. **Protection:** PS-014…PS-020 and PS-030, with PS-029 stress capture running during protection and supply-transient tests.
5. **Automotive supply profiles:** AUTO-001…AUTO-018, starting with non-destructive voltage ramps before severe pulses.
6. **Temperature corners:** TH-001…TH-005, TH-008 and TH-009 while repeating the most important baseline/dynamic tests.
7. **Functional-safety / combined corners:** FUSA-001…FUSA-010 as applicable, starting with threshold coordination and timing before destructive fault injection; execute FUSA-011 only for applicable 48 V/HV architectures.
8. **Endurance and margin:** LIFE-001…LIFE-004 after the design has passed short-duration tests; LIFE-005 only on sacrificial samples with independent safety cutoffs.
9. **EMC pre-compliance:** EMC-006 as soon as the layout is representative.
10. **Formal qualification:** TR-*, EMC-*, ENV-*, AUTO-019/020, TH-006/007/010/011, 48V-*, HV-* plus any safety rows requiring compliant external equipment or independent evidence.

## What the present bench can cover well

With the programmable power supply, electronic load, oscilloscope and thermal chamber, the highest-value immediately executable work is:

- input/output operating envelope;
- line/load regulation and efficiency;
- ripple/noise and load-transient response;
- startup, shutdown, UVLO, reset and recovery;
- overcurrent, short-circuit and thermal protection;
- jump-start/overvoltage/undervoltage tests when the source has sufficient voltage and slew rate;
- cold-crank and generator-profile replay when the source supports arbitrary waveforms;
- hot/cold operation, derating, thermal cycling and combined electrical/thermal tests;
- long-duration power cycling and operating-life tests;
- hot-plug overshoot, start-up into pre-bias/maximum capacitance, dropout and switching-frequency mapping;
- component-stress and derating measurements during all of the above (PS-029);
- threshold coordination, FTTI timing capture and many fault-injection pre-compliance cases (FUSA-002…FUSA-010), provided the DUT exposes safe injection points;
- combined-corner automation and post-stress drift checks using the mandatory execution metadata above.

The largest gaps for formal automotive qualification are a compliant **ISO 7637 transient generator**, a **load-dump generator** (ISO 16750-2 Test A/B), a **fast 4-quadrant amplifier/battery simulator** (1–2 ms edges for LV 124 E-02/E-05, superimposed AC up to 200 kHz), **CISPR 25 LISN/artificial network + EMI receiver**, **BCI RF system**, **ALSE chamber**, **ISO 10605 ESD gun**, an **insulation/hipot tester**, and mechanical/humidity/ingress facilities.

For design verification the highest-value additions are a **frequency-response analyzer with injection transformer** (PS-021…PS-023) and a **5 µH artificial network with spectrum analyzer and near-field probes** for pre-compliance (EMC-006).

## Evidence and traceability rules

1. **Requirement chain:** each executed row shall link requirement/analysis item → test ID → stimulus/fault → expected state → acceptance limit → evidence artifact.
2. **Safety timing:** where a fault can violate a safety goal, store fault onset, detection and final safe/degraded-state timestamps separately; do not retain only a single “reaction time” value.
3. **Pre/post comparison:** stress, environmental and endurance rows require a baseline and post-stress parameter set. Report drift even when both absolute measurements remain inside limits.
4. **Sample accounting:** record DUT serial/revision, sample count and rationale. A minimum standards sample count is not automatically a statistical demonstration of safety/reliability claims.
5. **Measurement decision:** keep raw measured value, limit, uncertainty/guard band and final verdict as separate fields.
6. **Recovery state:** PASS requires a defined end state: normal operation, specified degraded state or maintained safe state. “No visible damage” alone is insufficient for protection/fault rows.
7. **Tool evidence:** retain automation version/commit, instrument configuration, calibration status and error/status queues with the test result.
8. **Closed-source confidentiality:** reports may use generic basis labels such as “internal requirement” or “internal safety analysis”; proprietary document titles, filenames and confidential excerpts are not required in this matrix. Use controlled requirement IDs in the project traceability system when available.
